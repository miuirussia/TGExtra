# Продолжение на macOS: сохранение истории правок постов

## Задача и текущее состояние

Пользователь сообщил, что изменение поста не всегда сохраняется в истории,
попросил исправить это, затем сохранить инструкции для продолжения на macOS.
Исправления внесены, но ещё не скомпилированы и не проверены Swift-тестами.
Следующий шаг — запустить проверки на macOS, устранить найденные ошибки и
сообщить фактический результат пользователю.

Работа начата от коммита `673fddb` (`Update TGExtra.patch`). На момент создания
этого файла изменены:

- `Sources/tgapi/TLParser.swift` — реализация исправлений.
- `Tests/main.swift` — регрессионные проверки.
- `README.md` — описание поведения и ограничений истории.
- `NEXT.md` — эта передача контекста.

Изменения не закоммичены. При продолжении сначала проверь `git status` и diff:
после передачи могли появиться дополнительные изменения пользователя.
Не заменяй текущие файлы версиями из исходного коммита.

## Что изменено

1. Вместо общего FIFO для всех сообщений введён `_originalOrder` только для
   сообщений с одной версией. Лимит `maxTrackedOriginals = 2000` относится к ним.
   После первой правки сообщение исключается из этого FIFO: поток обычных
   сообщений больше не должен удалять накопленную историю. При загрузке
   сохранённых данных используется то же разделение. Формат UserDefaults
   `TGExtraEditHistoryByPeer` и миграция старого формата сохранены.
2. Текущий текст сравнивается с последней сохранённой версией вместо первой.
   Последовательность `A → B → A → C` должна полностью сохраняться.
   Повторная доставка одной и той же версии не должна создавать дубль.
3. Сняты запреты на пустой текст и флаг `out`: сохраняются удаление/добавление
   подписи и собственные правки. Трекер не подменяет текст для приложения.
   Для добавления новой отличающейся версии по-прежнему нужен `editDate`.
4. Добавлен трекинг для отдельного `Api.Message`, `DiscussionMessage`,
   `PeerDialogs`, `Dialogs` и `DialogsSlice`. Полные новые сообщения теперь
   проходят через тот же трекер, что и правки/загруженная история.
5. Добавлен `trackVersionsWithOpaquePeers`: при неудаче полного TL-разбора он
   читает известную часть ответа с сообщениями/обновлениями перед векторами
   пользователей и чатов. Покрывает 11 конструкторов: `messages`,
   `messagesSlice`, `channelMessages`, `discussionMessage`, `peerDialogs`,
   `dialogs`, `dialogsSlice`, `channelDifference`, `channelDifferenceTooLong`,
   `difference`, `differenceSlice`.
   Это путь записи истории, он не переписывает байты ответа и не заменяет
   существующую защиту удалений. Общая проверка `hasUnknownPeer` используется
   также существующим `patchUpdateVector` для `updates`/`updatesCombined`.
   Нельзя фиксировать частично разобранные данные просто при любой ошибке:
   обход допускается только при неизвестном конструкторе сопутствующего peer.
6. Уведомление `TGExtraMessageEditedRealtime` отправляется через главный поток,
   поскольку его обработчик в `UIHooks.xm` обращается к UI-узлам.

## Что уже проверено

В предыдущей среде был Linux, `swiftc` отсутствовал. Поэтому **успешная сборка
и прохождение Swift-тестов пока не подтверждены**.

Прошли:

- `python3 Tests/check_resources.py`.
- `git diff --check`.
- `bash -n Tests/run.sh`.
- Разовая статическая сверка числовых сигнатур всех 11 новых веток обхода
  с сериализаторами в `api_sources/Api36.swift`, `Api37.swift`, `Api41.swift`.

Эти проверки не заменяют компиляцию и выполнение тестов.

## Порядок продолжения на macOS

Запускай команды из корня репозитория; путь на Mac может отличаться от
`/Projects/TGExtra`, использовавшегося в Linux.

```sh
git status --short
git diff -- Sources/tgapi/TLParser.swift Tests/main.swift README.md
xcode-select -p
xcrun swiftc --version
bash Tests/run.sh
```

`Tests/run.sh` сам проверяет ресурсы, копирует Sources/Tests во временный каталог,
компилирует Objective-C-поддержку и Swift, запускает основной бинарник и второй
запуск с `--restore`. UserDefaults в этих тестах подменены хранилищем в памяти.
Прохождение `--restore` проверяет загрузку заранее подготовленных данных,
а не фактическую запись на диск между процессами.

Исправь ошибки компиляции или падения проверок, не ослабляя ожидаемое поведение.
Особенно проверь новую таблицу `historyReplies`, вложенные generic-функции
разбора и вставку байтов в `withOpaqueHistoryPeer`: этот код ещё не компилировался.
После исправлений повтори `bash Tests/run.sh` и `git diff --check`.

Если Theos и iOS SDK уже настроены, собери пакет:

```sh
make package FINALPACKAGE=1
```

Для проекта сохранены варианты rootful/rootless/roothide. Не считай отсутствие
локального Theos или SDK ошибкой самой реализации; отдельно укажи, какой этап
не удалось выполнить. Изменения видеоэкспорта к этой задаче не относятся.

## Что должны подтверждать регрессионные тесты

- `A → B → A → C`, повторные доставки без дублей.
- `Caption → пусто → Caption` и `пусто → Caption → пусто`.
- Запись собственных исходников/правок без изменения переданных приложению байтов.
- Отсутствие ложной истории при отличающемся тексте без `editDate`.
- Все 11 форм ответов: с известными peers, неизвестным Chat и неизвестным User.
- Запись правок из `otherUpdates` в ответах синхронизации.
- Отсутствие частичных записей от усечённых ответов с известными peers и
  некорректных счётчиков векторов.
- Сохранение истории после загрузки 2101 нового обычного сообщения при
  сохранении лимита в 2000 исходников без правок.
- Восстановление истории, включая пустые версии, при наличии более 2000
  сохранённых исходников без правок.
- Старые проверки антиудаления, TTL, gzip, контейнеров и исключений ghost mode
  продолжают проходить; изменение общего `hasUnknownPeer` не должно их ломать.

## Проверка на iOS, если доступно устройство

Включи Anti-Edit до получения исходного текста. Проверь чужой и собственный
пост канала, обычное сообщение и подпись медиа. Карандаш должен появляться при
правке в открытом чате, сохраняться после выхода/возврата и перезапуска.
Проверь получение правки после возвращения приложения из фона, историю через
список чатов/обсуждения и одинаковые message ID в разных каналах.

Если значка нет, отдели отсутствие сохранённых версий от ошибки извлечения
`peer`/message ID из UI-узла. Поиск истории требует ключ `peer + message ID`.
Диагностика сейчас отключена в обоих местах:

- `TLParser.swift`: `diagEnabled = false`.
- `Logger/Logger.h`: `TGEXTRA_DIAG 0`.

Для воспроизведения можно временно включить оба переключателя и сопоставить
`anti-edit VERSION`, `anti-edit persisted`, `tl-UNPARSED`, `node peer-key NOT FOUND`
и `edit-badge ... versions=...`. После диагностики верни release-настройки.

## Ограничения и оставшиеся вопросы

- Сохраняются только тексты, которые твик действительно получил при включённой
  функции. Уже потерянные и никогда не полученные версии восстановить нельзя.
- Лимит версий остался прежним: первый наблюдавшийся текст и 19 последних правок.
- Исходники без правок всё ещё пишутся с задержкой 5 секунд. Завершение приложения
  до записи может лишить будущую историю исходника; эта задержка не исправлена.
- Для сообщений без доступного исходника первая полученная правка становится
  первой наблюдавшейся версией и сама по себе не даёт карандаш.
- У `updateShortSentMessage` нет текста: снятие фильтра `out` само по себе не
  гарантирует захват исходника каждого локально отправленного сообщения.
- Обход неизвестных peers не решает неизвестные конструкторы самих Message,
  media или Update. Не пытайся искать TL-сигнатуры произвольным сканированием байтов.
- Проверка неизвестного peer не может полностью проверить неизвестный остаток
  пакета. Сохрани проверки известной части и минимальных размеров хвоста.
- Число сообщений с уже накопленной историей теперь не ограничено этим FIFO;
  объём UserDefaults может расти. Не возвращай общий лимит, стирающий историю,
  ради ограничения исходников.

В отчёте пользователю раздели реально пройденные тесты, сборку и проверку на
устройстве. Не заявляй, что исходная проблема подтверждённо исчезла на iOS,
если был выполнен только тестовый запуск на macOS.
